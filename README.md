# 聖杯戦争 観戦記

七騎のサーヴァントと七人のマスターが、ひとつの街で最長30日を戦う聖杯戦争シミュレーションです。プレイヤーは一陣営のマスターとして、要所で方針を決めます（すべておまかせにもできます）。サーヴァントは kagemiya@ふたば の設定をもとにした二次創作です。

- `index.html` … 観戦（ゲーム本体）
- `roster.html` … サーヴァント名簿（Wikiのページから取り込み・確認・手直し・書き出し）

ビルドは不要で、静的ファイルだけで動きます。

AIエージェント向けの英語の仕様書は `AGENTS.md` にあります（構造・データ形式・エンジンの規則・決断のキー・確認手順）。仕組みを変えたらこちらも更新してください。

## GitHub Pages で公開する

1. このフォルダの中身をリポジトリの直下に置いてプッシュする
2. リポジトリの Settings → Pages で「Deploy from a branch」、ブランチ `main`・フォルダ `/ (root)` を選ぶ
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける

`.nojekyll` は GitHub の Jekyll 処理を止めるためのファイルです（消さない）。

手元で確認するときは、フォルダで `python3 -m http.server` を実行して `http://localhost:8000/` を開きます。`index.html` をダブルクリックで開いた場合は公開データを自動で読めないので、画面の案内に従って `data/` のJSONを選んでください。

## 背景画像

観戦画面の上部の情景は、`img/scenes/` に画像を置くと差し替わります（無い場所はシードから描く街並み）。昼と夜の2枚で1組、まずは基本の6種類（市街地・住宅街・水辺・森・山と寺社・工場跡）の12枚があれば全場面が埋まります。サイズ・ファイル名・生成用の指示文は [img/scenes/README.md](img/scenes/README.md) にあります。場所と情景の対応は `js/names.js`（`scene`）、種類の一覧は `js/scenes.js` です。

## 見た目

色は `index.html` の先頭の `:root`（`--cyan`・`--gold`・`--seal` など）でまとめて変えられます。

## データの置き場所

```
data/
  manifest.json   … 読み込むファイルの一覧
  servants.json   … サーヴァント（名簿ツールの「公開用に保存」）
  overrides.json  … 効果・ステータスの手直し表（名簿ツールの「手直し表を保存」）
```

`manifest.json` の書き方：

```json
{
  "servants":  ["servants.json", "packs/追加分-2026-11.json"],
  "overrides": ["overrides.json"],
  "masters":   []
}
```

- `servants` に並べたファイルは全部読み込まれます。同じクラス・真名がいれば後ろのファイルが優先されます。
- `masters` には固定キャラのマスター（`master.js` の `createMaster` に渡す形式）の配列を入れたJSONを並べられます。半分くらいの確率でそこから選ばれ、残りは抽選です。

## 他の人の追加分をまとめる手順

方法A：1つにまとめる（ファイルが増えない）

1. 公開中の `roster.html` を開き、「ファイルを読む」で今の `data/servants.json` と、届いた追加分のJSON（または Wiki のページの .txt）をまとめて選ぶ
2. 要確認の印が付いたものを確認し、必要なら「編集」「ステータス編集」で直す
3. 「公開用に保存」で `servants.json`、「手直し表を保存」で `overrides.json` を書き出して `data/` を差し替える
4. プッシュ

方法B：束を足す（誰の追加か分かりやすい）

1. 届いたJSONを `data/packs/` に置く
2. `data/manifest.json` の `servants` にファイル名を1行足す
3. プッシュ

どちらの方法でも、ゲーム側は読み込むたびに今の規則で組み直します。辞書や規則（`js/effects.js`）を直せば、過去に取り込んだデータにも反映されます。

名簿ツールで手元に作った名簿は、同じサイトの `index.html` で「名簿ツールの名簿を使う」を押せば、公開前にそのまま試せます。

## kagemiya から名前で取り込む（GitHub Actions）

ページを貼り付けなくても、ページ名（真名）を入れるだけで取り込めます。Seesaa Wiki はブラウザから直接読むことを許していないので、GitHub 側で読みに行きます。

1. リポジトリの **Actions** →「**kagemiya から取り込み**」→「**Run workflow**」
2. 「取り込み方」と「ページ名」を入れて実行
   - **追加（ページ名を指定）**：`ルーカン、ペンテシレイア` のように「、」・カンマ・改行で区切る。ページ名が真名と違うときは、ページのURLをそのまま入れてもよい
   - **取り直し**：名簿にいる騎をWikiから読み直す。ページ名を空欄にすると全騎（64騎で数分）。読み取りの規則（`js/parser.js`）を直したあとに使うと、旧データが新しい読み取りで作り直される
3. 終わると `data/servants.json` を更新するプルリクエストができる。本文に「読み取ったスキル・宝具」「要確認」の一覧が出るので、確認してマージする（「main に直接反映」も選べる）

- 実行結果の画面（Summary）に同じ一覧が出ます。読み取ったWiki記法は「wiki-text」として2週間ダウンロードできます
- 取り込んだデータにはページ名（`page`）が入り、次からの取り直しはそのページを読みます。ページ名の無い古いデータは、真名 →「真名(クラス)」の順に探します
- プルリクエストが作れないと出たら、Settings → Actions → General の「Allow GitHub Actions to create and approve pull requests」を有効にしてください
- 手元でも `node tools/kagemiya.js add ルーカン`（取り込み）、`node tools/kagemiya.js show ルーカン`（読み取り結果を見るだけ）で動きます

## 名簿の内容を手で直す

FGO風ステータスの表を二重に読んでスキルが増えた、セリフのテンプレートや別キャラのセリフが混ざった、といったときは、名簿ツールで騎を開いて「**内容を編集**」を押します。

- **スキル・宝具**：1つずつ消す（×）・足す・名前やランクや説明を直す
- **セリフ**：「見出し：「セリフ」」の行をまとめて書き換え。テンプレートの行や別キャラの行は行ごと消す（見出しの「会話」「宝具」などはゲーム中の台詞に使われる）
- **解説・人物**、**プロフィール・因縁**も同じように直せる

直した内容は手直し表（`overrides.json` の `content`）に入り、Wikiから取り直しても残ります。各タブの「Wikiの内容に戻す」で元に戻せます。直したあとにWiki側が書き換わると「要確認」に出るので、見比べて直し直してください。公開するときは「手直し表を保存」で `overrides.json` も差し替えます。同じ名前のスキルが2つあるときも「要確認」に出ます。

## プレイヤーの判断

元にした「80億分の1」と同じく、ふだんは**重点**だけを決め、要所で**大きな決断**をします。

マスターとして始めると、記録が流れ出す前に案内が3枚出ます。

1. **マスターの紹介**：素性・出自・性格・願い・触媒・能力値（魔力量・魔術・体力・精神・幸運）
2. **サーヴァントの評価**：名簿の全騎と1対1で戦った場合の平均勝率から、S〜Dの5段階で評価（上位10%がS、30%までA、60%までB、85%までC、残りがD）。基礎戦闘力・宝具の威力の順位、長所と短所も出ます。今回の顔ぶれとの相性ではなく、その英霊そのものの強さの目安です
3. **最初の重点**：一日目の動き方を選ぶ（サーヴァントに合わせた★おすすめ付き）。選ぶまで一日目は始まりません

共有されたリンク（決断・重点の記録つき）で再現するときは、案内を出さずにそのまま進みます。

パソコンでは、重点の欄を見出しの「たたむ」で一行に格納できます（スマホの「重点：○○ ▾」と同じ）。たたんだ状態はブラウザに残ります。

- **重点**（いつでも変えられる・次の朝から反映）：おまかせ／攻め／守り／偵察／休養／潜伏／交渉。昼の行動、夜に出撃するか、戦い方（全力・様子見・すぐ退く）が決まる。おまかせは陣営の方針（開戦時にサーヴァントに合わせて決まる）どおりに動く
- **大きな決断**（止まって選ぶ）
  - 作戦会議（5日ごと）：状況に合う選択肢が最大3つ出る。拠点への総攻撃、令呪による強化、拠点の移動、同盟の申し込み、同盟の破棄と奇襲、真名の推理、使い魔で拠点を探す、霊脈で力を蓄える
  - 致命傷のとき：令呪で退かせる・令呪で奮い立たせる・使わない
  - 他の陣営からの同盟の申し出、討伐令、昼の街で敵マスターを見かけたとき
  - サーヴァントを失ったとき：教会に保護を求めて最後まで見届ける／教会に保護を求めて結末まで早送り／主を失ったサーヴァントと契約する（はぐれがいるときだけ。単独行動の日数だけ現界している）／他のマスターから令呪を奪う（成功はごくまれ。失敗すると多くは命を落とす）。運が悪いと、サーヴァントが消えたその場でマスターも命を落とす（`fallenDeath`）
  - マスターが死んだとき：ゲームオーバー。見届けるか早送りするかを選ぶ

### 真名の推理

教会は真名を教えません。戦った相手の戦い方、宝具の気配、偵察で得たものは**手がかり**として貯まり（陣営一覧に「手がかりN」と出る）、作戦会議の「真名を推理する」で当てられる見込みが上がります。外れても手がかりは1つ増えます。宝具を真名ごと聞いたり、偵察で見抜いたりすれば推理なしで分かります。

### マスターの性格（js/personas.js）

マスターには性格があり、方針の選び方・出撃・撤退・同盟・令呪・マスター狙い・終盤の裏切りなどが偏ります（冷徹な合理主義者、誇り高い魔術師、慎重な策略家、好戦的な戦闘狂、情に厚いお人好し、臆病な素人、狡猾な暗殺者、野心家）。他のマスターの性格は最初は分からず、戦ったあとに見えてくることがあります（`personaReveal`）。固定キャラのマスターには `"persona": "kind"` のように書けます。性格は `js/personas.js` に足せます。

### 戦闘中のマスター殺し

戦闘の打ち合いで押し勝った側の刃が、まれに相手マスターに届きます（`masterStrike`）。マスター狙いのスキル（気配遮断など）や暗殺者気質のマスターほど起きやすく、マスター防御・自分の工房で守られます。令呪で防げることもあります。

記録はふだん新しいものだけを表示し（パソコン10件・スマホ5件）、「すべての記録を見る」で枠の中をスクロールして全部読めます。

記録の上のボタンで絞り込めます。

- **★ ハイライト**：勝敗が決まったとき・令呪・同盟と裏切り・討伐令・因縁の再会・真名の看破・結末など大きな出来事。宝具を解放しただけでは入りません。戦いで脱落した記録は、とどめと決め手と一緒に書かれます（「〇〇の宝具『…』が勝敗を決定づけた。△△は消滅した。」「宝具『…』で追い詰めた〇〇が、とどめを刺した。」「〇〇がとどめを刺した。」）
- **自陣営**：あなたの陣営が関わった記録だけ
- **CSVで保存**：ここまでに表示された記録をCSVファイルで保存（Excelで開ける。まだ見ていない先の展開は含まない）

結末の画面には次のものが出ます。

- **他の六陣営の目的と歩み**（観測者なら七陣営）：マスターの願い・英霊の願い・方針から見た戦い方の狙い・戦った回数と倒した相手・最も多く刃を交えた相手・結末と、その陣営が主役の大きな出来事
- **絆の推移**：あなたの陣営の絆を日ごとに線で。サーヴァントを失ってからは点線。なぞると日ごとの値が出ます
- **決断の一覧**：何日目に何を問われ、何を選んだか（おまかせも含む）と、重点の移り変わり
- ハイライトを古い順に並べた「振り返り」と、「自陣営の記録を見る」「記録をCSVで保存」のボタン

## 中断と続きから・これまでの記録

- **中断**：観戦中の「中断」で最初の画面に戻ると、その位置が保存されます。ページを閉じたり再読み込みしたりしても、1日の始まりと決断のたびに保存されています。最初の画面の「**続きから**」で、中断したところから再開します（中断中の戦争は1つだけ。新しく開戦すると上書き）。決断の画面が出ているときは「いったん下ろす」で下ろしてから中断します
- **これまでの聖杯戦争**：終わった戦争は新しいものから10件まで最初の画面に残ります。「最初から見る」「結末だけ見る」で再生、「リンクをコピー」で共有用のURL。同じ戦争を再生し直しても記録は増えません
- **書き出し・読み込み**：「記録を書き出す」で記録と中断中の戦争をJSONファイルにし、別の端末やブラウザで「記録を読み込む」と取り込めます（同じ記録は重ならず、10件を超えた古いものは外れる）。「すべて消す」は元に戻せません
- 保存するのはシード・決断・重点だけで、再開や再生のたびに同じ戦争を組み直します。名簿が変わっていると同じ展開にならないため、そのときは確認が出ます
- 保存先はブラウザの `localStorage`（`hgw.save.v1`・`hgw.history.v1`）。件数は `index.html` の `HIST_MAX` で変えられます

自分のサーヴァントと、真名が分かったサーヴァントは、解説を読めます（左の「解説と資料を見る」、陣営一覧のⓘ、結末の表の真名）。Wikiの解説の冒頭と、Wikipedia（真名・元ネタで検索）と kagemiya@ふたば のページへのリンクが出ます。まだ真名を知らない相手のものは出ません。

「決断をおまかせ」を押すと、以後は止まらずに進みます。重点の変化と決断の内容はURL（`f=`・`c=`）に残るので、リンクを共有すると同じ戦争を再現できます。

## 日常と街の出来事

- **日常**（自陣営で1日40%）：食事（Wikiの好きなもの）、夜更けの会話（セリフの「会話」）、マスターが見るサーヴァントの過去の夢（解説の一文）、苦手なもの、聖杯への願い、外出、マスター自身の一日。**絆**が深まり、令呪の効き・撤退・踏みとどまり・制御のしやすさが少し良くなる
- **街の出来事**（1日25%）：霊脈の活性化、雨の夜（戦場が水辺扱い）、満月、祭り（その夜は誰も動けない）、使い魔、宝具の目撃と監督役の警告、討伐令（討った陣営に追加の令呪）
- **因縁**：Wikiの「因縁キャラ」に同じ戦争のサーヴァントの名前があれば、出会ったときに因縁の一文が出て、互いを狙いやすくなる

確率は `js/config.js` の `ENGINE`（`lifeChance`・`eventChance`・`councilEvery`）で変えられます。

## 戦争の進み方（js/engine.js）

1. **開幕**：名簿から7騎を選び（`war.js`）、マスターを抽選する。範囲ランク（`C～A`）はここで確定。プレイヤーの陣営を1つ選ぶ
2. **昼**：各陣営が行動を選ぶ。偵察（拠点・真名を探る）、工房強化、休養、同盟交渉、潜伏。狂化などで制御が効かないと勝手にうろつく。夕方に維持魔力を払う
3. **夜**：出撃するか籠もるかを決める。出撃側は索敵と相手の隠密で遭遇を判定し、相手の拠点なら拠点側に陣地・工房の補正が付く。気配を消せるサーヴァントはマスターを奇襲することがある
4. **戦闘**：最大4回の打ち合い。戦闘力（ステータスの重み付き平均×スキル効果）を比べ、宝具・特攻・魅了・会心・防御無視・即死・致命傷耐性・撤退と逃走阻止・令呪での離脱などが絡む。宝具を使うと真名がばれやすい
5. **脱落**：サーヴァントが消滅するとマスターは教会へ（プレイヤーは上の選択）。マスターが倒れたサーヴァントは単独行動の日数だけ残り、脱落したマスターと再契約することもある
6. **終幕**：最後の1騎が聖杯を手にする。30日で決着しなければ引き分け

同じシード・同じデータなら同じ戦争になります（URLの `?seed=` を共有すれば再現できます）。データが変わると同じシードでも別の戦争になります。

エンジンはジェネレーター（`warGen`）で、1日の始まり（`{type:'tick'}`、今の重点を渡して進める）と大きな決断（`{type:'decision'}`）で呼び出し元に戻ります。`runWar` はすべて「おまかせ」で最後まで進める版です。新しい決断を足すときは `engine.js` の `ask()` を、重点を足すときは `FOCUS` を使います。

## 調整する場所

| 変えたいこと | 場所 |
|---|---|
| 戦争の長さ、出撃・遭遇の頻度、ダメージ、令呪の使われ方 | `js/config.js` の `ENGINE` |
| 強さの差がどれくらい勝敗に効くか | `js/config.js` の `BATTLE_K`（大きいほど番狂わせが増える） |
| ステータスの重み・ランクの数値 | `js/config.js` の `STAT_W`・`RANK_SCORE` |
| クラスの追加・エクストラの紛れ込む確率 | `js/config.js` の `CLASS_DEFS`・`WAR` |
| マスターの名前・街・場所・願い（願いは出自・性格ごとの候補から選ぶ） | `js/names.js` |
| マスターの性格と、その偏り | `js/personas.js` |
| スキルの辞書・説明文の読み取り規則 | `js/effects.js` |

スキル辞書（`js/effects.js` の `SKILL_DICT`）には、原作（TYPE-MOON作品）のクラス別スキル・保有スキルの主なものが入っています（FGOに実装された470騎のスキルと照らし合わせ、2騎以上が持つ汎用的なスキルはすべて収録。「〇〇の神核」「〇〇の叡智」「〇〇の武練」のような系統は語尾で判定）。「黄金律(体)」のような変種は、辞書の効果に説明文から読んだ効果を足します。名前が一致すれば辞書の効果を使い、説明文に「直感と同等」「カリスマと軍略の複合スキル」のように書かれていれば、その効果も足します。「従者」「〇〇の加護」「〇〇の寵愛」のような一般的な言葉の名前は、辞書を土台に説明文の内容も合わせて決めます（名簿ツールでは「辞書＋推定」と表示され、要確認に出ます）。

`node test/sim.js 500` で500回戦争を回して、決着日数や勝率の偏りを確認できます。`node test/sim.js 1 <シード>` でその戦争の記録を表示します。`node test/interactive.js 200` は重点と決断をランダムに選んで、対話式の流れと再現性を確かめます。`node test/skills.js` はスキル辞書（原作のスキル名が辞書で決まるか）、`node test/content.js` は内容の手直し、`node test/kagemiya.js` は Wiki のHTMLからの読み取りを確かめます。

## マスターの設定

```js
{
  "name": "固定キャラ", "origin": "noble",        // 出自：noble / newblood / mercenary / civilian / irregular / 自由文字列
  "persona": "proud",                              // 性格（js/personas.js のキー）。書かなければ出自に合わせて抽選
  "stats": { "mana": "A", "mind": 70 },           // ランクでも数値でも可。書いていない能力値は出自から抽選
  "skills": [{ "name": "魔眼", "rank": "B", "desc": "…" }],
  "wish": "…",
  "custom": { "何でも": "入れてよい" }
}
```

マスターも Wiki と同じ書式（【氏名】【出自】【ステータス】魔力量：B 魔術：C 体力：D 精神：C 幸運：E、**スキル名：ランク）で書けば `HGW.master.parseMasterText` で読めます。
