# 聖杯戦争 観戦記

七騎のサーヴァントと七人のマスターが、ひとつの街で最後の一騎になるまで戦う（最長30日。10〜100日で変えられる）聖杯戦争シミュレーションです。プレイヤーは一陣営のマスターとして、日々の方針と要所の決断を選びます（すべておまかせにもできます）。サーヴァントは kagemiya@ふたば の設定をもとにした二次創作です。

- `index.html` … 観戦（ゲーム本体）
- `roster.html` … サーヴァントリスト（Wikiのページから取り込み・確認・手直し・書き出し）
- `submit.html` … 申請フォーム（プレイヤーが新しい英霊の申請や、英霊の調整の希望を管理者に届ける）

ビルドは不要で、静的ファイルだけで動きます。

AIエージェント向けの英語の仕様書は `AGENTS.md` にあります（構造・データ形式・エンジンの規則・決断のキー・確認手順）。仕組みを変えたらこちらも更新してください。

## GitHub Pages で公開する

1. このフォルダの中身をリポジトリの直下に置いてプッシュする
2. リポジトリの Settings → Pages で「Deploy from a branch」、ブランチ `main`・フォルダ `/ (root)` を選ぶ
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける

`.nojekyll` は GitHub の Jekyll 処理を止めるためのファイルです（消さない）。

手元で確認するときは、フォルダで `python3 -m http.server` を実行して `http://localhost:8000/` を開きます。`index.html` をダブルクリックで開いた場合は公開データを自動で読めないので、画面の案内に従って `data/` のJSONを選んでください。

## 開戦の設定

- **立場**：ひとつの陣営のマスター／すべてを知る観測者
- **進む速さ**：ゆっくり・ふつう・はやい・とても速い（8倍）。観戦中は上の 1×〜16× で変えられる
- **一言を残す**：節目で聞く（既定）／聞かない。前回選んだものが残る（下の「一言を残す」）
- **戦争の長さ**：10〜100日（既定は30日）。短いほど決着がつかないまま終わりやすい（10日だと多くは引き分け）。長くしても、ふつうは最後の一騎が決まった時点で終わる
- **七騎の選び方**：クラスごとに一騎（既定）／全騎から均等に。「全騎から均等に」では、クラスを気にせずリストの全員から同じ確率で七騎が選ばれ、同じクラスが何騎も並ぶことがある（（一）（二）と番号が付く）
- **エクストラクラス**：ときどき加わる（既定）／加えない。加えないと、ルーラーなどエクストラクラスの英霊は、代役としても呼ばれない
- **シード**

長さ・選び方・エクストラクラスは前回選んだものが残ります。どれも戦争の展開を変えるので、共有リンク（`d=`・`p=open`・`x=0`）、中断中の戦争、これまでの記録に一緒に保存され、再現するときはそれが使われます。

### 参戦サーヴァントの設定

最初の画面のいちばん下（強さランキングのリンクの下）に、折りたたんだ「参戦サーヴァントの設定」があります。戦争に呼ばれるサーヴァントを絞る機能です。真名がすべて見えてしまううえ、顔ぶれを選ぶとゲームのコンセプト（誰が来るか分からない）に反するので、目立たない場所に置いています。

- 全体の「全選択」「全解除」と、クラスごとの「全選択」「全解除」、騎ごとのチェックで選びます（既定は全員参戦）
- 外した騎は、七騎の抽選にも、クラスの代役にも呼ばれません。クラスの全員を外すと、その席は別のクラスの英霊が代役で埋めます
- 参戦するのが七騎に満たないと開戦できません
- 設定はこのブラウザに残ります（`localStorage` の `hgw.exclude.v1`）。何も外さなければ、今までと同じ戦争になります
- 外した騎は戦争の展開を変えるので、共有リンクの `ex=`（リストの番号を36進数にして `.` でつないだもの）、中断中の戦争、これまでの記録（`ex`）にその戦争の分が保存され、再現するときはそれが使われます。共有リンクで開いたときは、保存した設定ではなくリンクの設定になります

マスターの年齢は16〜46歳で、原作に倣って10代・20代がやや多めに出ます。

## アプリとして使う（PWA）

GitHub Pages で公開していれば、そのままアプリとしてホーム画面やパソコンに追加できます。

- Chrome・Edge（Android・パソコン）：最初の画面に「アプリとして追加する」ボタンが出ます（アドレスバーのインストールのアイコンからも可）
- iPhone・iPad：Safari の共有ボタンから「ホーム画面に追加」（最初の画面に案内が出ます）
- 一度開けば、電波のないところでも遊べます（`sw.js` が必要なファイルを保存しておく）。オンラインのときは常に最新のファイルを取りに行くので、更新はすぐ反映されます
- アイコンは `icons/` の仮のもの（令呪の紋様）。差し替え方とサイズは [icons/README.md](icons/README.md)
- アプリの名前と色は `manifest.webmanifest`
- `js/` にファイルを足したら、`sw.js` の `PRECACHE` にも足し、`VERSION` を1つ上げてください
- `index.html` をダブルクリックで開いた場合（file://）は、アプリとしては使えません

## データの置き場所

```
data/
  manifest.json   … 読み込むファイルの一覧
  servants.json   … サーヴァント（リストツールの「公開用に保存」）
  overrides.json  … 効果・ステータスの手直し表（リストツールの「手直し表を保存」）
  survival.json   … 生存曲線の集計（node tools/survival.js。リストを変えたら作り直す）
```

`manifest.json` の書き方：

```json
{
  "servants":  ["servants.json", "packs/追加分-2026-11.json"],
  "overrides": ["overrides.json"],
  "masters":   []
}
```

- `servants` に並べたファイルは全部読み込まれます。同じクラス・真名がいれば後ろのファイルが優先されます。
- `masters` には固定キャラのマスター（`master.js` の `createMaster` に渡す形式）の配列を入れたJSONを並べられます。半分くらいの確率でそこから選ばれ、残りは抽選です。

## 他の人の追加分をまとめる手順

方法A：1つにまとめる（ファイルが増えない）

1. 公開中の `roster.html` を開く（公開中のリストと手直し表が自動で読み込まれる）。届いた追加分のJSON（または Wiki のページの .txt）を「ファイルを読む」で選ぶか、ページを貼り付けて「リストに追加」
2. 要確認の印が付いたものを確認し、必要なら「編集」「ステータス編集」で直す。問題なければ詳細の要確認の欄の「確認した」で消せる（手直し表の `reviewed` に入る。取り直しても同じ内容なら出てこない。スキルの説明やランクが変わると、また要確認に出る。「確認済みの要確認」から戻せる）
3. 「公開用に保存」で `servants.json`、「手直し表を保存」で `overrides.json` を書き出す
4. リストツールの「公開・保存」の「**GitHub にアップロード**」で開く画面（`data/incoming/`）に、書き出したファイルをそのまま入れて「Commit changes」（ファイル名は `servants (3).json` のままでよい）。Actions の「データの反映」が差分を書いたプルリクエストを作るので、確かめてマージする（下の「データの反映」）
   - 今までどおり `data/servants.json`・`data/overrides.json` を直接差し替えてもよい。そのときも「データの反映」が動き、ゲームが動くかを確かめ、生存曲線の集計を作り直して main に入れる（差分は Actions の実行結果の画面に出る）

方法B：束を足す（誰の追加か分かりやすい）

1. 届いたJSONを `data/packs/` に置く
2. `data/manifest.json` の `servants` にファイル名を1行足す
3. プッシュ

どちらの方法でも、ゲーム側は読み込むたびに今の規則で組み直します。辞書や規則（`js/effects.js`）を直せば、過去に取り込んだデータにも反映されます。

リストツールで手元に作ったリストは、同じサイトの `index.html` で「リストツールで作ったリストを使う」を押せば、公開前にそのまま試せます。

## Wikiの記法の片付け（js/parser.js）

キャラシートを取り込むときと、公開中のデータを読み込むたびに、seesaawiki の記法を片付けます（取り込み直さなくても効きます）。

- **ルビ**：説明文では表記だけ残し（`&ruby(とうろう){蜻蛉}` → 蜻蛉）、宝具・武器の見出しでは**読み**として取ります（『&ruby(ひとたち){碁盤斬り}』 → 碁盤斬り（ひとたち））
- **脚注**：`((…))` の中身と、本文に残った番号（`*1`・`＊2`。見出しや宝具名の末尾も）を消す。`5*3` のような計算は残す
- **折りたたみ** `[+]見出し` `[END]`（見出しの文字は残す）、**画像** `&ref(…)`、**飾り** `&align(){}` `&color(){}` `&size(){}` など（入れ子も）、**実体参照** `&#339;`、対になっていない `''` を消す
- **表** `|a|b|` は「a：b／…」の文に直す（`|center:|c` のような書式だけの行は捨てる）
- **因縁キャラ**：`''[[名前]]''` や `[[名前]]：` だけの行と、その下の本文を1件として読む（1行の「名前：本文」も読む。セリフの見出しの行は因縁にしない）。公開中の因縁を読み直すには「kagemiya から取り直し」が要ります

`node test/markup.js` で確かめられます。

## データの反映（GitHub Actions「データの反映」）

`data/incoming/` にファイルを上げると、中身を見て反映し、何が変わったかを本文に書いたプルリクエストを作ります（`.github/workflows/data.yml`）。ファイル名は何でもかまいません。

> **最初に一度だけ設定が要ります**：リポジトリの Settings → Actions → General → Workflow permissions の「**Allow GitHub Actions to create and approve pull requests**」に印を付けて保存してください。これが無いとプルリクエストを作れず、反映したデータは `data/upload-番号` のブランチに置かれたまま main に入りません（実行は失敗の印になり、実行結果の画面に理由が出ます）。

| 上げるもの | 反映のしかた |
|---|---|
| リストツールの「公開用に保存」「リストをJSONで保存」 | 今のリストの8割以上の騎が入っていれば、まるごと置き換え（入っていない騎は外れる。本文に名前が出る）。少なければ、足す・置き換える。書き出しに残っていた手直しは手直し表に引き継ぐ |
| 「手直し表を保存」 | `overrides.json` をまるごと置き換え |
| Wikiのページのテキスト（.txt） | 英霊を足す・置き換える（複数ページは `=====` だけの行で区切る） |
| 申請・記録のファイルなど | 反映せずに残す（申請はリストツールの「取り込み」で読む） |

同じ種類のファイルが複数あるときは**上げた順**（古いもの → 新しいもの）に反映し、手直し表は**いちばん新しいものだけ**を使います（古いものは使わずに片付け、本文にそう書きます）。以前はファイル名の順だったので「overrides (10).json」が「(9)」より先に読まれ、古い方で上書きされることがありました。

新しいアップロードのプルリクエストを作ると、まだ開いている古いアップロードのプルリクエストは「新しい方にまとめた」と書いて自動で閉じます（古い方のファイルも新しいプルリクエストに含まれています）。アップロードのプルリクエストを**マージせずに自分で閉じた**ときは、Actions の「アップロードの片付け」（`.github/workflows/data-cleanup.yml`）が、そのとき反映するはずだったファイルを `data/incoming/` から消し、ブランチも消します。以前は閉じても `data/incoming/` にファイルが残り、次のアップロードのたびに古いデータがまた反映されていました。

プルリクエストの本文には、英霊の追加・削除・変更（スキル・宝具・セリフ・解説などどこが変わったか、戦闘力・宝具の威力・評価の変化）、評価だけ動いた騎、手直し表の表ごとの追加・変更・削除が出ます。反映のあと、ゲームが動くか（シミュレーション40回・FGO風の欄の読み飛ばし）を確かめ、生存曲線の集計（`data/survival.json`、3000回）を作り直します。

`data/servants.json`・`data/overrides.json`・`data/manifest.json`・`data/packs/` を直接変えたときも同じように動き、集計が合わなくなっていれば作り直して main に入れます（プルリクエストは作らず、差分は実行結果の画面に出る）。手元では `node tools/incoming.js`（反映）、`node tools/datadiff.js 変更前のdataフォルダ`（差分）で同じことができます。

**優勝率・生存曲線の数字**は `data/survival.json` の集計から出ています。集計とリストが合っていないあいだは、見た人のブラウザでそれぞれ800回ずつ計算し直す（数秒〜十数秒、数字は少し粗い）ので、上の流れで作り直されるのを待つのが確実です。開戦時の評価（S〜E）と1対1の平均勝率は、開くたびにその時のデータから計算するので、いつも最新です。

## 申請フォーム（submit.html）

プレイヤーが、新しい英霊の申請や、登録済みの英霊の調整の希望を管理者に届けるためのページです。サーバーは使わず、入力はその端末の中だけで処理します。ゲームの最初の画面の下と、英霊の解説の「この英霊の調整を希望する」から開けます。

- **新しい英霊を申請**：kagemiya のページ名を入れる（Wikiに載っていればそれだけでよい）。ページのテキストを貼り付けると、ゲームがどう読み取るか（ステータス・スキルの効果・宝具が攻撃か補助か・推定になっているところ・評価 S〜E）をすぐ確かめられます。「Wikiのページと同じ内容です」に印があれば、テキストは確かめるためだけに使い、申請にはページ名だけを入れます
- **登録済みの英霊の調整を希望**：英霊を選ぶ（`submit.html?servant=真名` でも開ける）
- どちらも、まず「**ゲームではこう判断されます**」が出ます（スキルのうち名前で分かったもの・説明から推定したもの・読み取れなかったもの、宝具が攻撃か補助か）。各スキル・宝具には効果と「**判断の理由**」（辞書にあるスキルだった／説明の言葉から推定した／攻撃の言葉があるので攻撃宝具とみなした…）が付きます
- 違っていたら、項目ごとの「**ここを直してほしい**」に文章で書けば十分です（ステータスにも欄があります）。読み取りの間違い（スキルではない行など）は「スキルではない（消してほしい）」に印を付けると、消した場合の評価がすぐ出ます。効果を自分で決めたい人は「効果を自分で指定する（くわしい人向け）」で、効果の種類と強さ・宝具の扱い（攻撃／補助）を直せ、評価・平均勝率・戦闘力・宝具の威力が「調整前 → 調整後」で出ます
- **セリフ・解説・プロフィール**：読み取った内容を、リストツールと同じ場面ごとの欄で直せます（直したところだけが申請に入る）。直すのが難しければ、それぞれの「直してほしいこと」の欄に文章で書くだけでもかまいません
- 理由・そのほか直してほしいこと・お名前・連絡先も書けます
- 届け方は3つ：**GitHub で申請する**（内容を書き込んだ Issue の画面が開く。GitHub のアカウントが要る）／**ファイルに保存**（申請の .json）／**文面をコピー**（X や Discord などで送る）。ページのテキストや書き換えたセリフが長くて Issue に入らないときは、ファイルを添付するよう案内が出ます（「GitHub で申請する」を押すとファイルも保存される）

管理者は、Issue の「管理者向け」の枠の中身をリストツールの「取り込み」の欄に貼り付けて「リストに追加」を押すか、申請のファイルを「ファイルを読む」で読みます。ページのテキストがあれば英霊を追加し、調整の希望は手直し表に、セリフなどの書き換えと「消してほしい」スキル・宝具は内容の手直しに入れ、申請者・理由・項目ごとの「直してほしいところ」を欄の下と、その英霊の詳細の上に出します（どれも未公開の変更なので、確かめてから公開する）。ページのテキストが無い追加申請は、「ページ名で取り込む」の欄にページ名が入るので、そこから GitHub の取り込みを実行します。

申請のファイルの形：`{ format: 'hgw-request', version: 1, kind: 'add' | 'adjust', servant, class, id, page, wiki, overrides: { servant, stats, np }, contentEdit: { voice, text, profile, relations }, drop: { skills, nps }, contentBase, notes: [{ target, text }], reason, content, from, contact }`（`overrides` は `overrides.json` と同じ形の一部。`contentEdit` は変えた見出し・項目だけ（`[]`・空文字は消す）、因縁はまるごと。`drop` は消してほしいスキル・宝具の番号と名前。`contentBase` はそのときのWikiの内容の目印）。

## 顔グラフィック

`img/faces/` に **真名.webp**（`.png`・`.jpg` も可。正方形 256px 程度）を置くと、ゲームで顔が出ます。真名を明かさないように、自分が引いたサーヴァントと真名が分かったサーヴァントだけに出ます（左の Servant の欄・陣営の一覧・解説の窓・結末の表）。画像の無い英霊がほとんどで構いません（無ければクラスのアイコンのまま、レイアウトは変わらない）。くわしくは `img/faces/README.md`。リストツールの各騎の詳細に、画像があるかと置くべきファイル名が出ます。

## クラスのアイコン

`img/classes/` に、七つのクラス（`saber` `archer` `lancer` `rider` `caster` `assassin` `berserker`）と、それ以外のクラス（ルーラーなど）用の `extra` のアイコンがあります（128×128 の WebP）。陣営の一覧・サーヴァントの欄・開戦の案内・結末の表・結末の画像・リストツールに出ます。差し替えるときは同じ名前・同じサイズで上書きし、`sw.js` の `VERSION` を1つ上げます。どのクラスがどの絵になるかは `js/config.js` の `classIcon`。

## リストツールの使い方（roster.html）

- **画面**：上のタブで「リスト」「取り込み」「試し戦い」「聖杯戦争で試す」「公開・保存」「人数・組み合わせ」を切り替えます（最後に開いていたタブと騎はブラウザに残る）
- **リスト**：左が一覧、右が選んだ騎の詳細です。一覧の行を押すと右に出ます。↑↓ または j・k キー、詳細の上の ‹ › で前後の騎へ。詳細にはステータス・顔グラフィック・スキル・宝具・要確認・セリフ・プロフィール・解説が並びます。スマホでは一覧 → 詳細（「← 一覧へ」で戻る）に切り替わります
- **公開中のリストから始まる**：開くと `data/` のリストと手直し表を読み込みます（ファイルを直接開いたときは読めないので「ファイルを読む」で）。2回目からは、このブラウザのリストと公開中のリストを見比べて「公開・保存」の「公開中のリスト」の欄に違いを出します（公開側に新しい更新があるときは、リストの上にも知らせとそろえるボタンが出ます）
  - **公開中のリストにそろえる**：Actions の取り込みなどで公開側が更新されたとき。公開側の更新を取り込み、このブラウザでした**未公開の変更（足した騎・直した騎・手直し）は残します**（最後にそろえた時点と比べて、どちらで変わったかを見分ける）
  - **公開中のリストで置き換える**：未公開の変更を捨てて、公開中のものに戻す
  - 未公開の変更がある騎には「未公開の追加」「未公開の変更」の印が付き、絞り込みの「未公開の追加・変更」で一覧にできます。公開するには「公開用に保存」「手直し表を保存」で書き出して `data/` の同じ名前のファイルと置き換えます
- **探す**：一覧の上の欄で、真名・クラス・元ネタ・スキル名・宝具名から探せます（ひらがな・カタカナ、全角・半角の違いは無視。「/」キーで欄へ、Enter で一覧の先頭を開く、Esc で消す）。並べ替えはクラス順・名前順・評価順・戦闘力順・宝具の威力順・要確認の多い順。絞り込みはクラス（選ぶ欄）と、要確認あり・未公開の追加・変更・内容を手直し中（押すたびに入・切）
- **評価**：各騎に S〜E の評価が付きます（ゲームの開戦時の評価と同じ式。リストの全騎と1対1で戦った平均勝率の順位）
- **聖杯戦争で試す**：このブラウザのリスト（未公開の追加・手直しも含む）で全自動の聖杯戦争をたくさん回し（300〜10000回）、英霊ごとの**総合の優勝率**（聖杯を手にした割合）と、半数が脱落する日を一覧にします。公開（アップロード）しなくても調整の結果が分かります。端末のCPUの数だけ並列で回すので、1000回なら十数秒ほど。リストを公開中の並びにそろえ、戦争の種も公開中の集計と同じにして回すので、3000回（既定）で何も変えていなければ公開中の数字（ランキングの優勝率）とぴったりそろい、「差」はそのまま変更の影響です（比べる相手は公開中の集計か、保存しておいた結果）。回数を減らすと、登場の少ない英霊ほど数字が揺れます。「設定の数値を試す」では js/config.js の数値（聖杯戦争の進み方・戦闘の勝率曲線・ステータスのスコアと役割・宝具の種別・クラスの燃費など）をこの試しのときだけ変えられ、よい値が見つかったら「config.js に書く値をコピー」で書き写せます（ゲームや公開中のリストには効きません）。優勝率の「±」は回数が少ないことによる揺れの目安です
- **試し戦い**：「試し戦い」のタブ。左右の欄に真名を打つと候補が出ます。各騎の「試し戦いの左に／右に」からも入れられます。「左の英霊と、リストの全騎との勝率を見る」で、勝ちにくい相手から全騎との見積もりが並びます（名前を押すと右に入る）
- **ページ名で取り込む**：「取り込み」の下の欄にページ名を入れて「名前をコピーして GitHub を開く」を押すと、名前をコピーした状態で Actions の「kagemiya から取り込み」が開きます（GitHub は実行画面に入力を渡せないので、「Run workflow」で貼り付ける）。各騎の「Wikiから取り直す」も同じで、その騎のページ名を「取り直し」で開きます。「kagemiya のページ」で Wiki の元のページも開けます
- **スキル・宝具の効果の見方**：効果ごとに「誰に掛かるか」（自分・相手・自分のマスター・相手のマスター・同盟相手）、「いつ働くか」（常に・宝具を使ったその戦いの間・この宝具を使ったとき・水辺でだけ・「竜」の相手と戦うときだけ・戦いごとに30%の確率で など）、「ゲームでの実際の働き」（ランクの倍率を掛けた強さで、例：「押し勝つたびに 4% の確率で相手を一撃で倒す」）が並びます。「編集」の画面でも、行ごとに同じ説明が入力に合わせて変わり、「効果の一覧」で全部の効果の意味を見られます。各行の下の**条件**欄で、効果が働く場面を絞れます：「条件」（水辺・森・山・夜・自分の拠点で・瀕死のとき＝霊基4割未満）、「相手」（その属性を持つ相手と戦うときだけ。男性・竜など）、「確率」（戦いごとに一度判定し、当たった戦いの間だけ働く。戦い以外の場面では強さ×確率）。組み合わせもできます。地形の条件は、戦いの中のどの場面（致命傷を受けたとき・宝具を使ったとき・撤退など）でもその戦いの地形で、戦いの外では拠点の地形で判定します（「自分の拠点で」は戦いの外では常に満たす）。説明文に「水辺や山で」のように条件が2つ書かれていれば、両方の効果になります。スキルに付けた宝具の消費・反動も宝具に掛かります。戦いの外でしか働かない効果（隠密・索敵・情報収集・自己回復など）に「戦いの始めに」などの発動を付けると、説明に「戦いの中で発動しても効かない」と出ます。状態異常（魅了・毒・スタン・混乱・宝具封印）の行には「名前」（石化・火傷・出血など、呼び名を変えられる）と「記録の文」（掛けたときに年代記に出る文。{S}＝掛けた側、{O}＝掛けられた側、{N}＝名前）の欄も出ます。申請フォームの「効果を自分で指定する」にも同じ欄があります。宝具の効果のうち戦いの効果は使ったその戦いの間だけ、昼・偵察・交渉・維持魔力などの効果は持っているだけで働きます
- **真名・クラスを変える**：詳細の「真名・クラスを変える」で、ゲームで使う真名とクラスを直せます（クラスは「セイバー」などの名前で。どれにも当たらなければエクストラクラス）。手直し表（`overrides.json` の `content` の `identity`）に入るので、Wikiから取り直しても残ります。効果・ステータス・宝具の扱い・ページ名の手直しは新しい真名へ引き継ぎます。「Wikiの表記に戻す」で元に戻せます
- **どの英霊にも当たらない手直し**：真名やスキル名が変わって、ゲームに届かなくなった手直しは「公開・保存」の「どの英霊にも当たらない手直し」に出ます（要らなければ消す）
- 知らせ（取り込んだ・保存した など）は画面の下に少しのあいだ出ます

## FGO風の欄と詠唱の行（読み取りで弾くもの）

Wikiのページに **【FGO風性能】** のような欄（レア度・霊基再臨・基本ステータス・所有カード・所有スキル（Skill1〜）・クラススキル・アペンドスキル・宝具・攻撃モーション・性能解説など）があっても、ゲームのスキル・宝具・ステータスとしては読みません。

- **取り込むとき**：「FGO」などを含む見出しの欄は、その下の小見出しも含めてまるごと読み飛ばします（中の「クラススキル」「宝具」で本来の欄に切り替わってしまうことがなくなった）。見出しが無くても、アペンドスキル・所有カード・攻撃モーション・Skill1〜 などが出たところから先を読み飛ばします
- **すでに取り込んだ英霊**：読み込むたびに、FGO風の項目（名前や、説明がFGO風の表・書き方のもの）と、その先のランクの無い項目を外します。宝具の説明の中の詠唱・セリフ（「万物に聖あり、…」など）が宝具として読まれていたものは、その宝具の説明に戻します。説明の無い「・神性：A」のような箇条書きのスキルが続き、その半分以上がすでに説明つきで出たスキルなら、ほかの欄のスキルのまとめとして一覧ごと外します（コンラの「・太陽弾」「・ルーン」など）。いまのデータでは16騎・85項目（ダナイデス・馬超・オルランドゥ・タリエシンなど）
- 外したものは、リストツールの各騎の「読み取りで外した項目」、申請フォームの「ゲームではこう判断されます」、Actions の取り込みのプルリクエストの本文に出ます。まだ混ざっているものは「内容を編集」で消せます
- 外したぶん戦闘力・宝具の威力が下がる騎があります（Skill1〜 の「仮の効果」や、詠唱の行が攻撃宝具とみなされていた分）。`node test/fgo.js` で確かめられます

## kagemiya から名前で取り込む（GitHub Actions）

ページを貼り付けなくても、ページ名（真名）を入れるだけで取り込めます。Seesaa Wiki はブラウザから直接読むことを許していないので、GitHub 側で読みに行きます。

1. リポジトリの **Actions** →「**kagemiya から取り込み**」→「**Run workflow**」
2. 「取り込み方」と「ページ名」を入れて実行
   - **追加（ページ名を指定）**：`ルーカン、ペンテシレイア` のように「、」・カンマ・改行で区切る。ページ名が真名と違うときは、ページのURLをそのまま入れてもよい
   - **取り直し**：リストにいる騎をWikiから読み直す。ページ名を空欄にすると全騎（64騎で数分）。読み取りの規則（`js/parser.js`）を直したあとに使うと、旧データが新しい読み取りで作り直される
3. 終わると `data/servants.json` を更新するプルリクエストができる。本文に「読み取ったスキル・宝具」「要確認」の一覧が出るので、確認してマージする（「main に直接反映」も選べる）

- 実行結果の画面（Summary）に同じ一覧が出ます。読み取ったWiki記法は「wiki-text」として2週間ダウンロードできます
- 取り込んだデータにはページ名（`page`）が入り、次からの取り直しはそのページを読みます。ページ名の無い古いデータは、真名 →「真名(クラス)」の順に探します
- **ページ名が真名と違うとき**（例：ハイヌヴェレのページは「ウンコ」）：リストツールで騎を開き、「Wikiのページ名」に入れて保存します。手直し表（`overrides.json` の `pages`）に入り、取り直しはこのページ名で行います（`page` より優先）
- 取り直しでページが見つからなかった騎には印（`pageMissing`：日付と試した名前）が付き、リストツールの一覧に「ページ名？」、絞り込みの「Wikiのページ名を確かめる」に出ます。取り込んだときのページ名が残っていない騎も同じところに出ます。プルリクエストの本文にも、試した名前と直し方が出ます
- プルリクエストが作れないと出たら、Settings → Actions → General の「Allow GitHub Actions to create and approve pull requests」を有効にしてください
- 手元でも `node tools/kagemiya.js add ルーカン`（取り込み）、`node tools/kagemiya.js show ルーカン`（読み取り結果を見るだけ）で動きます

## リストの内容を手で直す

FGO風ステータスの表を二重に読んでスキルが増えた、セリフのテンプレートや別キャラのセリフが混ざった、といったときは、リストツールで騎を開いて「**内容を編集**」を押します。

- **スキル・宝具**：1つずつ消す（×）・足す・名前やランクや説明を直す
- **セリフ**：ゲームで使う場面ごとに欄が並ぶ（下の表）。1行に1つ書き、テンプレートの行や別キャラの行は行ごと消す。上の丸い一覧で、どの場面にセリフがあるか（点線＝無い）が分かり、押すとその欄へ飛ぶ。宝具の欄の下には、宝具ごとに使える行があるかが出る。ゲームで使わない見出し（戦闘中の掛け声・霊基再臨など）は下にまとめて出て、どの表にも無い見出し（「その2」など）は黄色の枠で知らせる。見出しの名前を直すと、その場面で使われる。Wikiから貼り付けたいときは「まとめてテキストで」（「見出し：「セリフ」」の形）に切り替える
- **解説・人物**、**プロフィール・因縁**も同じように直せる

### セリフの見出しと、ゲームで使う場面

ゲームはWikiの【セリフ】の見出しの名前で行を選びます。別名の見出しも同じ場面の行として使います（表は `js/config.js` の `VOICE_SLOTS`）。

| 場面（見出し） | 別名 | ゲームのどこで |
|---|---|---|
| 召喚 | 自己紹介 | 開戦の日、あなたが召喚した場面 |
| 開始 | 戦闘開始 | 夜の戦いが始まる場面（仕掛けた側） |
| 宝具 | | 宝具の解放。その宝具の名前・読みを含む行を優先し、別の宝具の名前を含む行は使わない |
| 戦闘不能 | 消滅・退場 | 脱落の場面、倒れて終わったときの最後の一言 |
| 敗北 | | 倒れて終わったときの最後の一言（戦闘不能が無いとき） |
| 勝利 | | 勝ち残ったときの最後の一言（聖杯についてが無ければ結末の記録にも） |
| 聖杯について | 願い | 日常（聖杯の話）、聖杯が降臨する結末の記録 |
| 会話 | マイルーム・主従関係 | 日常（何気ない会話）、生き残って終わったときの最後の一言 |
| 好きなこと／嫌いなこと | | 日常（好きなものの話。嫌いなことは好きなことが無いとき） |
| 絆 | | 日常（絆が深まったとき）、終わったときの最後の一言 |

スキル・選択・攻撃・EX・宝具選択・ダメージ・霊基再臨・レベルアップ・最終・イベント・誕生日などは、今のゲームでは使いません（Wikiのテンプレートの見出しとして残しておいて構いません）。セリフの選び方は乱数ではなくシードで決まるので、**セリフの行を足したり直したりしても戦争の展開は変わりません**（ただし日常に使う場面のセリフが0行↔1行以上に変わると、その日常の出来事が起きる・起きないが変わります）。`node test/voice.js` で、場面ごとにセリフを持つ騎の数が見られます。

直した内容は手直し表（`overrides.json` の `content`）に入り、Wikiから取り直しても残ります。各タブの「Wikiの内容に戻す」で元に戻せます。直したあとにWiki側が書き換わると「要確認」に出るので、見比べて直し直してください。公開するときは「手直し表を保存」で `overrides.json` も差し替えます。同じ名前のスキルが2つあるときも「要確認」に出ます。

## プレイヤーの判断

元にした「80億分の1」と同じく、ふだんは**方針**だけを決め、要所で**大きな決断**をします。

マスターとして始めると、記録が流れ出す前に案内が3枚出ます。

1. **マスターの紹介**：名前・素性・出自・性格・願い・触媒・能力値（魔力量・魔術・体力・精神・幸運）。名前はくじで決まったものが入っていて、ここで自分で付けられます（20字まで。空欄でくじの名前に戻る。前回付けた名前も選べる）。名前は文面にしか出ないので、付けても戦争の展開は変わりません。共有リンク（`n=`）・中断・記録にも残ります
2. **サーヴァントの評価**：リストの全騎と1対1で戦った場合の平均勝率から、S〜Eの6段階で評価（上位10%がS、25%までA、45%までB、65%までC、85%までD、残りがE。Fateのランクに合わせてEまで。EXには「評価不能」の意味もあるので、最高はS。区切りは `js/config.js` の `GRADES`）。基礎戦闘力・宝具の威力の順位、長所と短所も出ます。今回の顔ぶれとの相性ではなく、その英霊そのものの強さの目安です
3. **最初の方針**：一日目の動き方を選ぶ（★おすすめ付き）。選ぶまで一日目は始まりません
   - おすすめは、同じ戦争を方針だけ変えて全自動で戦わせ、方針を変えずに最後まで戦ったときに最も勝ちやすかったものです（サーヴァントの評価ごと。`index.html` の `REC_FOCUS`）。今のデータでは、評価S・Aは「おまかせ」、B〜Dは「休養」、Eは「潜伏」（Eはどの方針でもほとんど勝てないが、潜伏がいちばん長く残れる）。おまかせは陣営の戦略に沿って、その晩の霊基や相手との力の差を見て出撃を決めるので、方針で毎晩の動きを固定するより勝ちやすい
   - 以前は特徴からおすすめを決めていました（強い英霊は「攻め」など）が、確かめると、おまかせの勝率16%に対して10%と、かえって下がっていました
   - `node test/focus.js` で確かめられます（約40秒）。エンジンや `config.js` の数値を変えたら回して、`REC_FOCUS` を見直してください

共有されたリンク（決断・方針の記録つき）で再現するときは、案内を出さずにそのまま進みます。

パソコンでは、方針の欄を見出しの「たたむ」で一行に格納できます（スマホの「方針：○○ ▾」と同じ）。たたんだ状態はブラウザに残ります。

- **方針**（いつでも変えられる・次の朝から反映）：おまかせ／攻め／守り／偵察／休養／潜伏／交渉。昼の行動、夜に出撃するか、戦い方（全力・様子見・すぐ退く）が決まる。おまかせは陣営の戦略（開戦時にサーヴァントに合わせて決まる）どおりに動く
- **大きな決断**（止まって選ぶ）
  - 作戦会議（5日ごと）：状況に合う選択肢が最大3つ出る。拠点への総攻撃、令呪による強化、拠点の移動、同盟の申し込み、同盟の破棄と奇襲、真名の推理、使い魔で拠点を探す、霊脈で力を蓄える
  - 致命傷のとき：令呪で退かせる・令呪で奮い立たせる・使わない
  - 他の陣営からの同盟の申し出、討伐令、昼の街で敵マスターを見かけたとき
  - サーヴァントを失ったとき：教会に保護を求めて最後まで見届ける／教会に保護を求めて結末まで早送り／主を失ったサーヴァントと契約する（はぐれがいるときだけ。単独行動の日数だけ現界している）／他のマスターから令呪を奪う（成功はごくまれ。失敗すると多くは命を落とす）。運が悪いと、サーヴァントが消えたその場でマスターも命を落とす（`fallenDeath`）
  - マスターが死んだとき：ゲームオーバー。見届けるか早送りするかを選ぶ

### 真名の推理

教会は真名を教えません。戦った相手の戦い方、宝具の気配、偵察で得たものは**手がかり**として貯まり（陣営一覧に「手がかりN」と出る）、作戦会議の「真名を推理する」で当てられる見込みが上がります。外れても手がかりは1つ増えます。宝具を真名ごと聞いたり、偵察で見抜いたりすれば推理なしで分かります。

### マスターの性格（js/personas.js）

マスターには性格があり、戦略の選び方・出撃・撤退・同盟・令呪・マスター狙い・終盤の裏切りなどが偏ります（冷徹な合理主義者、誇り高い魔術師、慎重な策略家、好戦的な戦闘狂、情に厚いお人好し、臆病な素人、狡猾な暗殺者、野心家）。他のマスターの性格は最初は分からず、戦ったあとに見えてくることがあります（`personaReveal`）。固定キャラのマスターには `"persona": "kind"` のように書けます。性格は `js/personas.js` に足せます。

### 戦闘中のマスター殺し

戦闘の打ち合いで押し勝った側の刃が、まれに相手マスターに届きます（`masterStrike`）。マスター狙いのスキル（気配遮断など）や暗殺者気質のマスターほど起きやすく、マスター防御・自分の工房で守られます。令呪で防げることもあります。

記録はふだん新しいものだけを表示し（パソコン10件・スマホ5件）、「すべての記録を見る」で枠の中をスクロールして全部読めます。

記録の上のボタンで絞り込めます。

- **★ ハイライト**：勝敗が決まったとき・令呪・同盟と裏切り・討伐令・因縁の再会・真名の看破・結末など大きな出来事。宝具を解放しただけでは入りません。戦いで脱落した記録は、とどめと決め手と一緒に書かれます（「〇〇の宝具『…』が勝敗を決定づけた。△△は消滅した。」「宝具『…』で追い詰めた〇〇が、とどめを刺した。」「〇〇がとどめを刺した。」）
- **自陣営**：あなたの陣営が関わった記録だけ
- **CSVで保存**：ここまでに表示された記録をCSVファイルで保存（Excelで開ける。まだ見ていない先の展開は含まない）

結末の画面には次のものが出ます。

- **他の六陣営の目的と歩み**（観測者なら七陣営）：マスターの願い・英霊の願い・戦略から見た戦い方の狙い・戦った回数と倒した相手・最も多く刃を交えた相手・結末と、その陣営が主役の大きな出来事
- **絆の推移**：あなたの陣営の絆を日ごとに線で。サーヴァントを失ってからは点線。なぞると日ごとの値が出ます
- **決断の一覧**：何日目に何を問われ、何を選んだか（おまかせも含む）と、方針の移り変わり
- ハイライトを古い順に並べた「振り返り」と、「自陣営の記録を見る」「記録をCSVで保存」のボタン

## 中断と続きから・これまでの記録

- **中断**：観戦中の「中断」で最初の画面に戻ると、その位置が保存されます。ページを閉じたり再読み込みしたりしても、1日の始まりと決断のたびに保存されています。最初の画面の「**続きから**」で、中断したところから再開します（中断中の戦争は1つだけ。新しく開戦すると上書き）。決断の画面が出ているときは「いったん下ろす」で下ろしてから中断します
- **これまでの聖杯戦争**：終わった戦争は新しいものから10件まで最初の画面に残ります。「最初から見る」「結末だけ見る」で再生、「リンクをコピー」で共有用のURL。同じ戦争を再生し直しても記録は増えません
- **書き出し・読み込み**：「記録を書き出す」で記録と中断中の戦争をJSONファイルにし、別の端末やブラウザで「記録を読み込む」と取り込めます（同じ記録は重ならず、10件を超えた古いものは外れる）。「すべて消す」は元に戻せません
- 保存するのはシード・決断・方針だけで、再開や再生のたびに同じ戦争を組み直します。リストが変わっていると同じ展開にならないため、そのときは確認が出ます
- **記録の整理**：記録ごとに「☆ 保護する」と「消す」があります。保護した記録は10件の数に含まれず、外すか消すまで残ります（30件まで）。「すべて消す」は保護したものも消します
- 保存先はブラウザの `localStorage`（`hgw.save.v1`・`hgw.history.v1`）。件数は `index.html` の `HIST_MAX`（保護したものは `KEEP_MAX`）で変えられます

## 一言を残す

80億分の1の「思いを残す」に倣い、マスターとして節目に一言を残せます。開戦の設定の「一言を残す」を「聞かない」にするか、問いの画面の「これからは聞かない」で止められます。

- 聞くのは、初めての戦いのあと・折り返し（戦争の長さの半分）・自分のサーヴァントを失ったとき・終幕（結末を出す前）。同じ日に節目が重なったら一番大きなもの1つだけを、次の日に移る前に聞きます。残さずに「やめておく」もできます
- 残した言葉は記録の欄にその位置で出て（ハイライトと自陣営にも入る）、結末の「あなたが残した言葉」、これまでの記録の一覧、結末の画像に並びます
- 結末には、サーヴァントの最後の一言も出ます（Wikiのセリフから。勝てば「勝利」「聖杯について」、消えていれば「戦闘不能」「消滅」など。場面と見出しの対応は「セリフの見出しと、ゲームで使う場面」の表。選び方はシードで決まる）
- 言葉は中断の保存と記録（`w`）に入ります。URLには入りません。記録の再生や共有リンクの再現では聞かれません

## 画像にする

戦争が終わったら、結末の「画像にする」でPNG画像を作れます（ブラウザの canvas で描くので、サーバーは使いません）。3つの見本が並ぶので、選んでから保存します。

- **結末のまとめ**：勝者、あなたの陣営の歩み、絆、サーヴァントの最後の一言とあなたの一言、七陣営の結末、シード
- **サーヴァントの評価**：呼んだ英霊の開戦時の評価（S〜E・平均勝率・基礎戦闘力・宝具の威力・ステータス・長所と短所）と生存曲線
- **両方をつなげた一枚**：結末のまとめの下に、サーヴァントの評価をつなげたもの
- 選んだ画像は「保存する」でダウンロード、共有できる端末（スマホなど）では「共有する」も出ます。「← 選び直す」でほかの画像に戻れます
- 観測者として見た戦争は、結末のまとめだけです

## 強さランキング（ranking.html）

すべての英霊の強さを見比べるページです。真名が分かってしまう（戦争の中で推し量る楽しみが減る）ので、ゲームの最初の画面では、開戦するボタンや記録よりも下、いちばん下の説明の中にだけリンクを置いています。

- 列：評価（S〜E）・優勝率（生存曲線と同じ集計で、出た戦争のうち勝ち残った割合と出た回数）・生存（半分が脱落するまでの日数。「最後まで」は半分以上が最後の日まで残った）・平均勝率（全騎と1対1）・戦闘力・宝具の威力・攻め／守り／粘り／隠密／索敵（ステータスとスキル・宝具の効果を合わせた得意分野。リストの中での順位で S〜E）
- 見出しを押すと並べ替え、真名を押すと、省略されていない真名・ステータス・目立つ効果・宝具が開きます。クラスで絞ったり、真名・元ネタで探したりできます
- 集計は `data/survival.json` を使い、リストが違うときはこのブラウザで800回まで回します（ゲームの解説の生存曲線と同じ集計を共有）。リストツールで作ったリストを使っているときは `ranking.html?data=local`

## 生存曲線

サーヴァントの解説（左の「解説と資料を見る」、陣営一覧のⓘ、開戦の案内）に、その英霊が何日目まで生き残れるかの曲線が出ます。今回の戦争ではなく、リストから毎回ランダムに七騎を選んで全自動で戦わせたたくさんの聖杯戦争（既定の設定：30日・クラスごとに一騎・エクストラときどき）で、その英霊が呼ばれたときの総合的な見込みです。点線はリスト全体の平均。

- 集計は `data/survival.json` にあり（`node tools/survival.js` で作る。既定3000回、約20秒）、リストの指紋が合えばそれを使います
- リストが変わって指紋が合わないとき（リストツールで作ったリスト、ファイルを直接開いたときなど）は、画面の側で少しずつ800回回して作り、このブラウザに残します（`hgw.survival.v1`）。集計の途中でも、それまでの結果で曲線が出ます
- Actions の「kagemiya から取り込み」と「データの反映」が、データが変わったときに集計を作り直します（`servants.json` や `overrides.json` を直接差し替えたときも、「データの反映」が自動で作り直して main に入れる）。手元では `node tools/survival.js`（`--check` で合っているかだけ確かめられる）

自分のサーヴァントと、真名が分かったサーヴァントは、解説を読めます（左の「解説と資料を見る」、陣営一覧のⓘ、結末の表の真名）。Wikiの解説の冒頭と、生存曲線、Wikipedia（真名・元ネタで検索）と kagemiya@ふたば のページへのリンクが出ます。まだ真名を知らない相手のものは出ません。

「決断をおまかせ」を押すと、以後は止まらずに進みます。方針の変化と決断の内容はURL（`f=`・`c=`）に残るので、リンクを共有すると同じ戦争を再現できます。

## ステータスの解説

ステータスや能力値にマウスを重ねる（スマホはタップ、キーボードはTabで移る）と、それが戦いの何に効くかの短い解説が出ます。

- サーヴァント：筋力・耐久・敏捷・魔力・幸運・宝具（左の欄と、開戦時の評価）。クラスで重みが変わる場合はそれも出ます
- 状態：霊基・魔力・絆・工房・令呪（左の欄、スマホの上の帯、令呪の紋様）
- マスター：魔力量・魔術・体力・精神・幸運（開戦時の紹介）
- 開戦時の評価：平均勝率・基礎戦闘力・宝具の威力

解説の文は `index.html` の `TIPS` にあります。具体的な数値や計算式は出さず、何に効くかだけを書いています。効き方を変えたときは文も直してください。

## ステータスの役割

宝具を除くどのステータスも、戦闘力（重み付きの平均）に関わるほか、それぞれ別の場面に効きます。

| ステータス | 効く場面 |
|---|---|
| 筋力 | 打ち勝ったときに与える傷が深くなる |
| 耐久 | 受ける傷が浅くなり、致命傷で踏みとどまりやすい |
| 敏捷 | 撤退で逃げ切る・逃げる敵に追いすがる、夜に敵を捉える・捉えられにくい |
| 魔力 | 宝具の威力が増し、宝具発動に要する魔力が減る。魔力による攻撃は、対魔力による影響を受けやすい |
| 幸運 | クリティカルヒットが出やすく、即死を免れやすく、致命傷でも命拾いしやすい |
| 宝具 | 宝具そのものの評価。戦闘には使わない（宝具の強さは宝具それぞれのランクと種別、そして魔力で決まる） |
| マスターの魔力量 | 魔力の蓄えと毎日の戻り |
| マスターの魔術 | 工房づくり・偵察がうまくいきやすい、戦いでのわずかな援護（ほかに真名の推理・使い魔） |
| マスターの体力 | 刃や奇襲が届いても生き延びやすい |
| マスターの精神 | 令呪が揺らがず、奮い立たせる令呪の力が増す。心が弱いと令呪が届かないことがある。サーヴァントが魅了や弱体化に呑まれにくく、制御の難しい英霊を抑えやすい |
| マスターの幸運 | 夜に見つかりにくい、マスターを狙う刃や奇襲をかわしやすい |

マスターの能力値はサーヴァントのステータスより小さめに効きます。強さは `js/config.js` の `STAT_FX` でまとめて変えられます（ランクの偏差に掛ける係数。C相当で効果なし、A相当で係数とほぼ同じだけ効く）。速さで振り切った・頑強な霊基で踏みとどまった・心が揺らいで令呪が届かなかった、などは記録にも出ます。

同じシードの戦争でも、この変更より前とは展開が変わります（以前の共有リンクは別の戦争になります）。

## 記録の文面

記録の文面は `js/names.js` の `LINES` にまとめてあり、同じ出来事でも並べた中から1つが選ばれます。選び方は乱数ではなくシードと記録の位置で決まるので、文面を足したり直したりしても戦争の展開は変わりません。`{S}`（サーヴァント）・`{M}`（マスター）などの差し込みは、キーごとに使えるものが決まっています（`names.js` の説明を参照）。

## 日常と街の出来事

- **日常**（自陣営で1日40%）：食事（Wikiの好きなもの）、夜更けの会話（セリフの「会話」）、マスターが見るサーヴァントの過去の夢（解説の一文）、苦手なもの、聖杯への願い、外出、マスター自身の一日、稽古、生前の話（人物・性格の一文）、傷の手当て（霊基が減っているとき）、すれ違い、見張り、星を見上げる夜。**絆**が深まり（すれ違いは少し浅くなる）、令呪の効き・撤退・踏みとどまり・制御のしやすさが少し良くなる
- **街の出来事**（1日25%）：霊脈の活性化、霊脈の乱れ（どの陣営も魔力が減る）、雨の夜（戦場が水辺扱い）、満月、聖杯の鳴動（どの陣営も出撃しやすい）、夜霧（互いを見つけにくい）、監督役の巡回（どの陣営も出撃を控える）、祭り（その夜は誰も動けない）、使い魔、宝具の目撃と監督役の警告、討伐令（討った陣営に追加の令呪）、街の噂（まだ拠点の分からない敵の噂。たどるか聞き流すかを選ぶ）
- **因縁**：Wikiの「因縁キャラ」に同じ戦争のサーヴァントの名前があれば、出会ったときに因縁の一文が出て、互いを狙いやすくなる

確率は `js/config.js` の `ENGINE`（`lifeChance`・`eventChance`・`councilEvery`）で変えられます。

## 戦争の進み方（js/engine.js）

1. **開幕**：リストから7騎を選び（`war.js`）、マスターを抽選する。範囲ランク（`C～A`）はここで確定。プレイヤーの陣営を1つ選ぶ
2. **昼**：各陣営が行動を選ぶ。偵察（拠点・真名を探る）、工房強化、休養、同盟交渉、潜伏。狂化などで制御が効かないと勝手にうろつく。夕方に維持魔力を払う（バーサーカーは重い。燃費のスキルで増減。休養・潜伏の日は霊体化して節約）。**足りない分はマスターの生命力から吸い上げ**、マスターが倒れかけると令呪一画を魔力に換えてしのぎ、令呪も無ければマスターが力尽きる
3. **夜**：出撃するか籠もるかを決める。出撃側は索敵と相手の隠密で遭遇を判定し、相手の拠点なら拠点側に陣地・工房の補正が付く。気配を消せるサーヴァントはマスターを奇襲することがある
4. **戦闘**：最大4回の打ち合い。戦闘力（ステータスの重み付き平均×スキル効果）を比べ、押し勝った側が傷を与える。押し負けた側も、戦闘力が拮抗しているほど大きな傷を返す（`counterDmg`）。宝具・特攻・魅了・先手・クリティカルヒット・防御無視・即死・致命傷耐性・撤退と逃走阻止・令呪での離脱・作っておいた道具などが絡む。**状態異常**：毒（打ち合いのたびと翌日に霊基を削る。毒では倒れない）、スタン（その打ち合いは宝具を使えず、戦闘力が半分）、混乱（戦闘力が下がり、自分を傷つけることもある）、宝具封印（その戦いの間、宝具を使えない）。状態異常耐性・精神耐性・耐久・マスターの精神で防げる。**先手の付いた宝具**は戦いの始めに切れる：その宝具の先手も先手の判定に足し、先手を取れたら1回目の打ち合いの頭でその宝具を放つ（魔力が足りるときだけ。退く戦い方では使わない）。宝具を使うと真名がばれやすい。戦いにも魔力を使い、バーサーカーは打ち合いのたびに魔力を食う。バーサーカー（と制御困難の強い英霊）は魔力が尽きても止まらず、魔力を顧みずに宝具を放つ（1回の戦いに一度。足りない分はマスターの生命力から）
   - **守りの効果の重なり**：被ダメージ軽減・回避・魔術耐性は、スキル・宝具・道具などの分を足したあと「重なるほど鈍る」形（合計 x → x ÷ (1 + x)。0.3 → 0.23、1.0 → 0.5）にしてから使います。被ダメージ軽減は「打ち合いの勝ちやすさ（守りとして戦闘力）」と「受ける傷の軽減」の両方に効くので、足したままだと重ねるほど極端に硬くなっていました。鈍り方は `ENGINE.defSoft`（0 で以前と同じ）、戦闘力に足す割合・傷の軽減の割合と上限は `defPowerW`・`defCap`・`guardDmgW`・`guardDmgCap` で、「聖杯戦争で試す」で試せます
   - **精神耐性**：魅了・混乱を防ぐほかに、相手の弱体化（威圧・幻惑・呪いなど）の効きを減らし（`ENGINE.mentalDebuff`）、相手の不意打ち（先手・強襲）に動じず（`mentalSurprise`）、傷を負っても戦闘力が落ちにくくなります（`mentalWound`、心が折れない）。重なると守りの効果と同じように鈍ります。以前は魅了・混乱を持つ英霊が少ないため、精神耐性を持つ47騎から取り除いても優勝率がほぼ変わりませんでした（−0.02ポイント）。今は＋0.4ポイントほど。傷の分（`mentalWound`）を上げるほど効きますが、硬くて傷を負いながら勝ち続ける英霊（ユーグ・ド・パイヤンなど）ほど得をします。「聖杯戦争で試す」で調整できます
   - **弱体化の種類**：弱体化は「精神弱体」（威圧・恐怖・幻惑など心への干渉。精神耐性とマスターの精神で防ぐ）、「肉体弱体」（呪い・衰え・重圧など体への干渉。耐久と対魔力で防ぐ）、種類を決めていない「弱体化」（精神耐性で少しだけ防ぐ）の3つ。合わせて戦闘力を最大5割まで下げる。Wikiの説明文の言葉（恐怖・威圧／呪い・衰弱など）や、辞書のスキル（呪術・対英雄は肉体、幻術・傾国の寵姫は精神…）で振り分けます。防ぎ方の強さは `ENGINE.mindDebuffGuard`・`bodyEndGuard`・`bodyMagicGuard`
   - **衰弱**：押し勝つたびに（既定。発動のしかたで変えられる）相手の戦闘力を少しずつ削り、重なっていく（上限 `witherCap`）。戦いが終わっても残り、毎朝 `witherFade` の確率で抜ける（休んだ翌朝は抜けやすい）。耐久と対魔力で防げ、弱体解除で消える。一人の相手に何度も挑む英霊ほど効く
   - **自分に掛ける不利な効果**：弱体化（3種）・衰弱・毒・スタン・混乱・宝具封印は、効果の行の「自分に掛ける」に印を付けると自分に掛かる（防げない）。デメリットの表現や、日ごとに弱っていく英霊に（衰弱を自分に掛けると既定で毎朝重なり、朝になっても消えない。弱体解除では消える）
   - **見切り・反撃**：見切りは押し負けた一撃を確率でかわして傷を受けない（相手の必中で減る。上限 `dodgeCap`）。反撃は押し負けて傷を受けても立っていれば、その傷の一部を相手に返す。発動のしかたに「攻撃を受ける直前に」を足したので、「斬られる直前に守りを固める」スキルも作れる（ここで得た守り・見切りはその一撃から効く）
   - **数値の見直し**：英霊の半数に「Bランク相当の同じ量」の効果を足して1万回・6千回ずつ回し、優勝率がどれだけ上がるかで揃えました（戦闘力+10%で約+1.6ポイント）。守りが攻めより得をしていたので——
     - 致命傷耐性（戦闘続行）の基準値を35%から20%に（同じ量で戦闘力上昇の2.6倍効いていた）、自己回復の休養での回復を 自己回復×60 から ×30 に（`regenHeal`）、被ダメージ軽減が戦闘力に効く割合を0.5から0.4に（`defPowerW`）
     - クリティカルヒットは基準値を10%から15%、倍率を1.5倍から2倍に（`critMult`）し、それが致命傷なら相手の踏みとどまる確率を半分にする（`critGuts`。1.5倍では確率10%でも傷が平均5%増えるだけで、ほとんど効かなかった）。宝具強化の基準値を15%から25%に（宝具を切った打ち合いはもともとほぼ勝つので、伸びしろが小さかった）
     - 索敵は持つほど損だった（見つけるほど戦いが増える・昼に偵察ばかり選ぶ）ので、偵察の重みを下げ（`detectScout`）、見つける力を弱め（`detectFind`）、代わりに迫る相手に先に気づいて見つかりにくく（`detectWary`）、先に見つけて仕掛けたときは少し有利に（`detectEdge`）
   - **同盟**：同盟は**三者まで**組める（`ENGINE.allianceMax`。同盟にいる陣営が外の陣営を誘う・外の陣営が同盟に加わる）。同盟の外に2騎以上残るときだけ組み、残り4騎で裏切りが起き、3騎で解ける。
     - **共闘**：同盟相手が戦っている夜に**加勢に来る**ことがある（拠点を守る戦い・同じ夜に出撃している・統率のスキルで来やすい）。加勢した味方は戦闘力の一部を足し、宝具も使い、押し負けたときは代わりに一撃を受けることもある（深手を負うと退く）
     - **共同作戦**：同盟ごとに夜ごと `jointOp` の確率で、そろって同じ敵（包囲網の的、いなければ同盟の外でいちばん手強い陣営）を狙うと決める。その夜は出撃しやすく（`jointHunt`）、狙いがそろい、加勢にも来やすい（`jointJoin`）
     - **支え合い**：毎朝、魔力の乏しい味方に余裕のある味方が魔力を分け（`allyManaShare`）、治療のスキルを持つ英霊が味方の傷を手当てし（`allyHeal`）、道具を2つ以上持つ味方が持たない味方に1つ回す
     - **包囲網**：ほかより多く討っている陣営（`coalitionAt` 騎以上。討伐令も数える）が現れると、ほかの陣営は手を組みやすくなり（`coalitionAlly`・`coalitionAllyW`）、同盟を組む陣営はその陣営を狙いやすくなる（`coalitionTarget`）
     - 同盟の申し出・交渉を選ぶ重みも上げた（`allyAccept`・`allyActW`）。500回で、同盟は1回の戦争に0.6→1.8、加勢の入った戦いは0.75→2.6、三者同盟は0.55、包囲網は約1回
5. **発動する効果**：スキル・宝具の効果ごとに「発動」を選べます——常に／戦いの始めに／打ち合いのたびに／押し勝ったとき／攻撃を受ける直前に／押し負けたとき／瀕死になったとき（1回の戦いに一度）／宝具を使ったとき／相手を倒したとき／毎朝（戦いの外）。「魔力」を入れると発動のたびにその魔力を払い（足りなければ発動しない。「打ち合いのたびに＋魔力」で、魔力がある限り自動で発動）、「回数」で1回の戦いの上限を決められます。発動して得た強化はその戦いの終わりまで（打ち合いのたびのものはその打ち合いだけ、毎朝のものは次の朝まで——昼の偵察・潜伏・夜の索敵など戦いの外にも効く——、相手を倒したときのものは次の戦いの終わりまで）。宝具の効果は空欄なら使った瞬間から、「押し勝ったとき」などを選ぶと使ったあと押し勝つたびに発動します。
   その場で働く効果：回復（既定は瀕死のとき）・体力吸収（押し勝ったとき）・魔力回復（戦いの始め）・魔力吸収（押し勝ったとき）・強化解除（相手がその戦いで得た強化を消す。「止める効果」を選ぶと、相手のその効果だけを、常に持っている分も含めて止める）・弱体解除（自分の状態異常を消し、その戦いの間は相手の弱体化・状態異常を弱める）・自己強化解除（名前を書いたスキル・宝具の効果、または「止める効果」で選んだ効果だけを、その戦いの間止める。両立しない効果の切り替えに。例：宝具Bに「自己強化解除：宝具A・特攻」を付けると、Bを使った戦いではAの特攻だけが消える）・スキル封印（相手の発動する効果を止める）。ほかに FGO を参考にした効果：宝具チャージ・ダメージカット・ダメージプラス・必中・かばう。リストツールと申請フォームの効果の選択肢は、攻め・守り・回復・吸収・弱体・解除・宝具などのジャンルごとに分けてあります
   **宝具の発動のしかた**：宝具ごとに、AIが選んで使う（いままでどおり）のほかに、**常時発動**（効果はスキルと同じに持っているだけで働く。宝具として「使う」ことはなく、毎日の維持魔力が宝具の消費×`npAlwaysUpkeep`だけ増える）と、**自動で発動**（戦いの始め・押し勝ったとき・押し負けたとき・瀕死になったとき・致命傷を受けた瞬間に、AIの判断を待たずに発動。1回の戦いに一度、消費は宝具の消費×`npAutoCost`）を選べます（リストツールの宝具の編集「発動のしかた」、申請フォームでも選べる）。説明文に「常時発動型」「常時展開型」などとある補助宝具は、読み取りで常時発動になります（要確認に出る）。致命傷の瞬間に発動した宝具で霊基が戻れば、そのまま踏みとどまります。強さの倍率 `npAlwaysScale` と2つの魔力の値は「聖杯戦争で試す」で試せます
6. **脱落**：サーヴァントが消滅するとマスターは教会へ（プレイヤーは上の選択）。マスターが倒れたサーヴァントは単独行動の日数だけ残り、脱落したマスターと再契約することもある
7. **終幕**：最後の1騎が聖杯を手にする。30日で決着しなければ引き分け。最後の二騎が相討ちになったとき（押し勝った側も深手で倒れることがある）や、最後に残った1騎がマスターを失っていて単独行動でも現界を保てないときは、聖杯を手にする者のいない**全滅**で終わる（単独行動の日数が残っていれば、マスターなしで聖杯を手にする）

同じシード・同じデータなら同じ戦争になります（URLの `?seed=` を共有すれば再現できます）。データが変わると同じシードでも別の戦争になります。

エンジンはジェネレーター（`warGen`）で、1日の始まり（`{type:'tick'}`、今の方針を渡して進める）と大きな決断（`{type:'decision'}`）で呼び出し元に戻ります。`runWar` はすべて「おまかせ」で最後まで進める版です。新しい決断を足すときは `engine.js` の `ask()` を、方針を足すときは `FOCUS` を使います。

| スキルの辞書・説明文の読み取り規則 | `js/effects.js` |

スキル辞書（`js/effects.js` の `SKILL_DICT`）には、原作（TYPE-MOON作品）のクラス別スキル・保有スキルの主なものが入っています（FGOに実装された470騎のスキルと照らし合わせ、2騎以上が持つ汎用的なスキルはすべて収録。TYPE-MOON Wiki のスキル一覧から、神速・クイックドロウ・戦闘加速・蛮勇・獅子心・至誠・護国の鬼将・仁王立ち・竜の心臓・受肉精霊・医神などの名前で意味の決まるスキルも足しています。辞書にも説明文にも手がかりが無いスキルは、FGO に同じ名前のスキルがあれば、その働き（攻撃力アップ・回避・ガッツなど）を借ります（`js/fgoskills.js`。[Chaldea](https://github.com/chaldea-center/chaldea) のデータ chaldea-data から `node tools/chaldea.js <chaldea-dataのフォルダ>` で作り直せる。リストツールでは「FGOより」と表示）。「〇〇の神核」「〇〇の叡智」「〇〇の武練」のような系統は語尾で判定）。「黄金律(体)」のような変種は、辞書の効果に説明文から読んだ効果を足します。名前が一致すれば辞書の効果を使い、説明文に「直感と同等」「カリスマと軍略の複合スキル」のように書かれていれば、その効果も足します。「従者」「〇〇の加護」「〇〇の寵愛」のような一般的な言葉の名前は、辞書を土台に説明文の内容も合わせて決めます（リストツールでは「辞書＋推定」と表示され、要確認に出ます）。

`node test/sim.js 500` で500回戦争を回して、決着日数や勝率の偏りを確認できます。`node test/sim.js 1 <シード>` でその戦争の記録を表示します。`node test/interactive.js 200` は方針と決断をランダムに選んで、対話式の流れと再現性を確かめます。`node test/skills.js` はスキル辞書（原作のスキル名が辞書で決まるか）、`node test/content.js` は内容の手直し、`node test/kagemiya.js` は Wiki のHTMLからの読み取り、`node test/survival.js` は生存曲線の集計と、名前を付けても展開が変わらないこと、`node test/focus.js` は最初の方針のおすすめが本当に勝ちやすいかを、`node test/effects.js` はスキル・宝具の効果の部品がすべてゲームに届いているか（読まれずに「反映されない」部品が無いか）と、真名・クラスの手直しを確かめます。

## マスターの設定

```js
{
  "name": "固定キャラ", "origin": "noble",        // 出自：noble / newblood / mercenary / civilian / irregular / 自由文字列
  "persona": "proud",                              // 性格（js/personas.js のキー）。書かなければ出自に合わせて抽選
  "stats": { "mana": "A", "mind": 70 },           // ランクでも数値でも可。書いていない能力値は出自から抽選
  "skills": [{ "name": "魔眼", "rank": "B", "desc": "…" }],
  "wish": "…",
  "custom": { "何でも": "入れてよい" }
}
```

マスターも Wiki と同じ書式（【氏名】【出自】【ステータス】魔力量：B 魔術：C 体力：D 精神：C 幸運：E、**スキル名：ランク）で書けば `HGW.master.parseMasterText` で読めます。
